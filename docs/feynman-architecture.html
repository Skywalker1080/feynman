§1 System context — two processes, one pipethe whole picture

The client is a thin renderer: it never touches the model, filesystem or SQLite. All agent logic lives in the server, which the client spawns or attaches to as a background process. The contract between them is JSON over HTTP for control-plane calls and one SSE stream per turn for data-plane events.

§2 Monorepo topology — who depends on whomturbo · 3 packages

Hard client/server split: the client is a pure consumer of the server's HTTP+SSE API and never imports server code. Both packages depend on the shared @feynman/types package. The server is the single source of truth for provider, tools, prompts and persistence.

§3 Bootstrap — from `feynman` to a ready sessionsequence

If the health check already passes, the client attaches to the running server instead of spawning one — so the second terminal window connects instantly and shares ~/.feynman/sessions.db. A stale server is simply the last one spawned; a fresh kill/restart cycle is re-verified end-to-end.

§4 One user turn — the full pathsequence · SSE back

The server streams one SSE response per turn; the client's eventsource-parser feeds each parsed event to a reducer in conversation.ts. Unknown event types are ignored — the contract is additive, so the plain-mode renderer and future clients keep working.

§5 The agentic tool loop — maxSteps 25multi-step function calling

The Vercel AI SDK executes the whole agentic loop server-side: it sends tool_calls back to execute(), injects the results as role:'tool' messages, and re-invokes the model until it stops calling tools or maxSteps (25) is hit. Each completed step is persisted immediately via onStepFinish — no batching, so a crash never loses a finished step.

§7 Persistence & resumeSQLite · /resume picker

preview = (SELECT content FROM messages WHERE session_id = s.id AND role='user' AND content IS NOT NULL ORDER BY id DESC LIMIT 1)

Sessions resume with the full message history replayed into the transcript, and the conversation is reconstructed server-side into CoreMessage[] so the model continues with complete context. The /resume <id> fast path still works — the picker is the primary path.

§8 Config & provider selectionprecedence chain

Adding a provider = one case in the factory + a Config field. The LanguageModel interface is the seam — session-loop.ts never knows which provider is in use. Allowlist is advisory: off-list models still run, with a once-per-session disclaimer.

§9 Cancel & abort path — Ctrl+C2 presses

The AI SDK does not abort-check by itself — it relies on the provider stream honoring abortSignal. That's why the cancel test uses a custom abort-aware ReadableStream whose pending pull rejects with AbortError. A hung run_terminal is killed through this same path.
